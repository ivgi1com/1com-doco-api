   mode-switch button used generic `text-ink` on the amber/teal mode-tint

   pairing the rest of the bar uses (commit `1bf9dab`).
6. Ran the `code-review` skill (medium, `--target=main`) as the fallback
   for the unstarted Vercel `react-best-practices` skill. It found real
   bugs, all fixed this session (not yet committed as of this file's last
   edit — check `git log` / `git status`):
   - **Race condition**: `usePlayground`'s `send()` `setTimeout` was never
     cancelled, so switching mode or endpoint mid-request let a stale
     `finish()` silently overwrite state with the wrong mode/endpoint's
     response. Fixed with a request-token ref checked inside `finish()`,
     plus clearing the timeout/interval on endpoint change, mode-switch
     confirm, and unmount. The mode-switch button is now also disabled
     while `sending`.
   - **Curl samples were malformed**: joined lines with the literal
     two-character string `\n` instead of a real line break (`" \\n"` vs
     `" \\\n"` in source). Affected every curl tab on the reference pages
     and the Playground code preview. Fixed; pinned with a unit test.
   - **Python samples could corrupt string content**: the regex-based
     true/false/null → True/False/None rewrite ran over the whole
     `JSON.stringify` output, so a *string* value literally equal to
     `"true"`/`"false"`/`"null"` got corrupted too. Replaced with a proper
     recursive `pythonLiteral()` serializer. Pinned with a unit test.
   - **Path-parameter substitution only replaced the first occurrence**
     of a repeated `{param}` placeholder (latent — no current endpoint has
     one). Fixed in both `lib/code-samples.ts` and
     `playground/request-builder.tsx` (`.replace` → `.replaceAll`).
     Pinned with a unit test.
   - **`buildSearchIndex()` recomputed on every `SiteHeader` render.**
     Added `getSearchIndex()` (a lazy module-level cache) in
     `lib/search-index.ts`; `SiteHeader` now calls that instead.
   - **Acknowledged, not fixed**: `use-playground.ts`'s sessionStorage-backed
     API-key sync duplicates the pattern `shell/theme.ts` already uses for
     localStorage (different pub/sub mechanism — window event vs. a Set of
     listeners). Flagged as a reasonable future simplification, not
     addressed this session to avoid also touching `theme.ts` for a
     non-bug.

## Two documentation-level tensions worth a decision at the gate

Neither silently resolved; both flagged in `docs/CURRENT_STATUS.md` too.

1. `design-system/MASTER.md`'s home-page anti-pattern list (and `impeccable`'s
   own bans) flag "identical card grids" as a SaaS cliché. The home page's
   3-card grid (Reference/Guides/Playground) is close to that shape — kept
   deliberately (3 genuinely different destinations, no eyebrow/hero-metric
   anti-patterns), but worth a second look.
2. MASTER.md's "controls 36px tall (32px in dense Playground mode)" and its
   general "touch targets ≥ 40px on touch devices" responsive rule are in
   tension for Playground's dense controls (filter input, param fields,
   mode-switch button, all 32px). Read the specific dense-mode exception as
   controlling; didn't silently change either rule.

## Key design and implementation choices already made (unchanged from before)

- Breakpoints, mobile disclosure/aside pattern for the request panel,
  synthetic-content labelling, and the Playground plan (mode bar, Demo/Live
  behavior, masked session-only API key) are all as previously documented
  and now implemented exactly as planned — see `CURRENT_STATUS.md` for the
  as-built inventory.
- Playground deliberately double-mounts its request/response panes for the
  <md step-flow and the md+ 3-pane layout (CSS-hidden, not JS-unmounted) —
  the same pattern `endpoint-view.tsx` already uses for its mobile/desktop
  `RequestPanel`. Shared `usePlayground` state keeps values in sync; each
  instance's own local UI state (JSON-viewer collapse state, search query)
  does not, which only matters if a viewer resizes across the `md` breakpoint
  mid-session — accepted as a low-probability edge case, consistent with the
  existing precedent.
